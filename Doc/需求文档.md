# NewLife.Holiday 需求文档

> 版本：v1.0 | 日期：2026-10-16

本文档描述 NewLife.Holiday（中国节假日识别库）的愿景、核心目标和功能方向。完成状态在[功能清单](功能清单.md)中追踪，详细设计在[架构设计](架构设计.md)中展开。

## 1. 背景与愿景

### 1.1 系统定位

中国节假日与调休识别类库（NuGet 包 `NewLife.Holiday`）：面向 .NET 全生态（net45 至 net10），从 NuGet 引用后一行代码判断任意日期是否放假、是否调休上班。

- **给谁用**：需要在业务逻辑中判断工作日/节假日/调休的 .NET 应用（考勤、排班、计费、工作流等）。
- **解决什么问题**：节假日与调休安排每年由国家发布且历年不同（含周末调休上班），业务系统不应硬编码判断逻辑。
- **离线可用**：内置历年安排数据，不依赖任何在线接口。

### 1.2 愿景

- **数据内置、判定准确**：逐年收录节假日安排（含调休），判断结果与官方一致。
- **未来可推算**：已发布数据之外的年份，按固定规则与农历推算法定节日（元旦/春节/清明/劳动/端午/中秋/国庆）。
- **地区扩展**：支持地方性假期（广西三月三）。
- **中国日历能力**：附带农历（干支/生肖/中文文本）与 24 节气计算。
- **全平台兼容**：主流 RID（win-x64/linux-x64/linux-arm64/linux-loongarch64）单元测试与 NativeAOT 全面覆盖。

### 1.3 核心竞品（待补充调研）

架构设计前由用户提供核心竞品（1~2 个）并轻量记录，供架构设计参考；完整调研见 `Doc/竞品分析.md`。

公开生态的常见同类项目（如 `chinese-days`、`chinesecalendar` 等，**未核实**）多以内置年度数据 + 规则推算为主流做法。本节待后续用「竞品分析」agent 专项调研补全。

## 2. 核心目标

| 编号 | 目标 | 所属层级 | 一句话描述 |
|------|------|----------|------------|
| HOL | 假期数据与判定 | 核心层 | 内置历年节假日数据，判定任意日期放假/上班，并推算未来年份 |
| LUN | 农历 | 基础层 | 公历转农历，提供干支、生肖与中文文本 |
| SOL | 节气 | 基础层 | 计算 24 节气日期与时刻，并定位最近节气 |
| QA | 工程与质量保障 | 基础设施 | 多 RID 单元测试与 NativeAOT 兼容冒烟全覆盖 |

## 3. 功能需求

### 3.1 HOL — 假期数据与判定

- **HOL-1 节假日数据加载**：从嵌入式 CSV 资源加载历年节假日与调休安排（中国、广西），构建有序假期列表。
- **HOL-2 中国假期判定**：`IsChinaHoliday` 判断指定日期是否放假（数据命中 + 周末兜底）。
- **HOL-3 固定节日推算**：无数据年份按规则推算元旦、春节、清明、劳动节、端午、中秋、国庆（春节/端午/中秋依赖农历）。
- **HOL-4 广西假期**：`IsGuangxiHoliday` 在中国假期基础上叠加广西三月三（数据 + 农历推算）。

### 3.2 LUN — 农历

- **LUN-1 公历转农历**：给定公历日期得到农历年/月/日，闰月单独标识（月份规格化为 1-12）。
- **LUN-2 干支生肖与中文文本**：天干地支年、生肖、中文月/日文本与字符串表示。

### 3.3 SOL — 节气

- **SOL-1 节气日期与时刻**：计算任意年份 24 节气的公历日期与本地时刻（精确到分钟）。
- **SOL-2 最近节气**：给出与指定日期最近的节气及带符号天数差。

### 3.4 QA — 工程与质量保障

- **QA-1 多平台单元测试矩阵**：win-x64 / linux-x64 / linux-arm64 原生 runner + 龙芯 LA64（QEMU）全量单测，push/PR 触发。
- **QA-2 NativeAOT 兼容冒烟**：同一冒烟程序在运行时与 NativeAOT 两种形态下运行固定场景，覆盖 win-x64 / linux-x64 / linux-arm64 / linux-la64。

## 4. 🧊 暂缓清单

| 功能 | 暂缓理由 | 解冻前提 |
|------|----------|----------|
| 2020 年之前的历史数据 | 业务使用集中在近年，补录工作量在数据整理 | 出现明确历史年份查询需求 |
| 广西以外的地区性假期 | 需求未明确，数据整理成本高 | 出现明确的地区性假期需求 |
| 高精度天文节气算法（VSOP87 级） | 当前简化模型时刻误差在 ±15 分钟内，满足日期级判断 | 出现分钟级精度要求 |

## 5. 不做什么

- 不做非节假日类日历服务（黄历宜忌、择日等）。
- 不依赖在线数据接口，判定必须离线可用。
- 不覆盖农历支持范围（约 1901-2100 年）之外的日期。
